# V1 form: harness-generated PDF

Status: decided for Kriday's personal v1; issues #2 and #4 remain open.

## Decision

Kriday runs a coding-agent harness on his computer to research a PlayStation game and generate a phone-readable PDF platinum route. V1 ships when he can use it for his Mortal Kombat run. He transfers the PDF to his phone and uses his PDF reader's annotations to mark progress. The PDF must remain readable offline; generation needs the harness's web access. The harness supplies its own tools and credentials: v1 does not require a separate application API key.

The v1 surface is a harness conversation: provide the game and any relevant constraints, generate a sourced route, and receive a PDF file for transfer. The document should accommodate phone reading and annotations, identify sources, and surface uncertainty rather than invent results. The reader's annotations are the progress record; there is no application-managed sync, account, or live progress service. Annotations need not feed back into the harness.

## Alternatives

- A local web app adds a server and phone connectivity or export without improving this personal workflow enough to justify it.
- A standalone CLI adds a separate interface around a harness Kriday already uses; the harness conversation is the interface.
- A deployed site adds hosting and multi-user concerns before they are needed. It is a separate later effort.

## Open dependencies and portability

Assume #2 can express its eventual ordered route, guide, or dependency view in a legible PDF. #2 still owns route structure and detail; if it requires interactive dependencies, automatic progress tracking, or live mid-run help, a static annotated PDF cannot deliver those features and this form must be revisited. PDF annotations provide manual progress only.

Assume #4 can use the harness's search and text-generation capabilities for this personal run; #4 still owns the actual generation approach, cost, latency and credentials. If it chooses a standalone API or a backend unavailable through the harness, the generation workflow and key handling change, and a small application or CLI may become necessary. AI remains limited to web search and text generation; PDF rendering is ordinary software.

The route content, source attribution, and document layout can inform a public site, subject to source rights. The personal harness session, its credentials and tooling, manual file transfer, PDF-reader annotations, and local-only operation do not become a hosted multi-user service automatically. A public site would need its own generation backend, credential and cost model, hosting, and any desired progress storage; none is committed for v1. Respect source access restrictions and reuse rights; do not assume attribution alone permits republication.
